Current state of the Mixology class email workflow, mapped from the two recipes, the two skills, and the runners. No interview was conducted. This document can claim what the files say; it cannot claim how often the second slice is actually invoked.

A class has a date, a page, and notes. The outcome is a scheduled Brevo draft that sells that class without burning the voice and measurement discipline of the rum, absinthe, World Whisky, and Cocktail Foundations sends.

The scoreboard is already named: clicks and ticket sales. Opens are directional because Apple Mail Privacy Protection inflates them.

Sugar House Brevo Compose Playbook

Purpose

Take a finished, user-edited Sugar House campaign brief and build a Brevo draft the user can approve: composed HTML, UTM-coded links, the hero image named in the brief, the correct audience, and the scheduled send time.

This file is the recipe for the second slice of the class-email workflow. The Cursor skill (sh-email-compose) is the initializer and the Brevo gotcha list. The workflow lives in this folder.

Scope

Compose HTML, host the image, create or update a Brevo draft, and set recipients plus scheduledAt. Stop there.

Do not send, do not click send-now, and do not rewrite brief copy. If the copy is wrong, send it back to the brief workflow.

class-campaign-playbook.md ends at the brief. This playbook starts after the user has edited that brief and added the hero image filename and location.

Handoff contract

The brief is locked copy. Treat every subject, preview, headline, paragraph, callout, and button label as final.

The brief must include a hero image block:

### Hero image
**Filename:** <file.jpg>
**Location:** <absolute or workspace path to the file or its folder>
**Alt:** <one factual sentence>
**Linked URL:** <optional, already UTM-tagged>

Asset: is an accepted alias for Location. A live HTTPS URL in Location is fine; skip a local copy if that URL already returns 200.

Honor DONT USE and struck sections. Omit them.

If Filename or Location is missing, stop and ask. Do not hunt Downloads. Do not generate a substitute hero.

Minimum input

  • The campaign brief under content/campaigns/<series-slug>.md
  • Which email to build, when the brief contains more than one

Optional:

  • Audience override (otherwise use the brief, then the live default below)
  • Send-time override (otherwise use the brief)

Do not make the user restate stable Sugar House context. Load it.

Source priority

  1. The campaign brief for copy, subject, preview, CTA labels, and UTMs
  2. email/compose.mjs for HTML structure (the source of record, not the master template file)
  3. Live destination pages for link truth
  4. Live Brevo for sender, audience IDs, cadence, and existing drafts
  5. Client canon for voice, measurement, and operating rules

When the brief and a live page disagree, flag it and do not ship the broken version. When a prior sent campaign and compose.mjs disagree, trust compose.mjs plus the current chrome rules in that file.

Phase 1: Initialize

Read these before composing:

  1. .claude/CLAUDE.md
  2. measurement-plan.md (UTM vocabulary and email steer)
  3. context.yaml
  4. brand-narrative.md
  5. email/compose.mjs
  6. email/SESSION-INIT-email-campaigns.md (account rules only; this workflow is a write, so the orientation read-only rule does not apply)

Confirm live Brevo state this session:

  • accounts_get_account is "The Sugar House" (jason@forke.co)
  • Sender: info@sugarhousedetroit.com. Resolve the sender id live (it has been 3). Use the name Sugar House Detroit, never [DEFAULT_FROM_NAME]
  • Lists and segments by name, then IDs. IDs drift; do not copy them into this playbook
  • Recent sent campaigns, current drafts, and anything queued
  • Cadence: no more than two marketing sends per week per contact

Review at least one relevant sent campaign's HTML so the new send matches the live block system. The rum series is the quality example for story-led content: eyebrow, headline, greeting, short paragraphs, image, callout, close.

Phase 2: Read the brief and lock destinations

Read the brief to completion. For the email being built, extract:

  • Subject and subject alternative (use the primary subject unless the user picks the alternative)
  • Preview / preheader
  • Eyebrow, headline, body, callout, secondary note, close
  • Campaign slug and send term
  • Send date and time (America/Detroit)
  • Audience named in the brief
  • Every CTA URL

Verify each destination this session with a live fetch:

  • HTTP 200
  • Path has a trailing slash before the query string
  • Page content matches the claim in the email (class date, menu name, hours, reservation rule)

Sugar House sugarhousedetroit.com links always take the five-parameter set from measurement-plan.md:

  • utm_source=brevo
  • utm_medium=email
  • utm_campaign = the initiative in the brief (never the individual send)
  • utm_content = placement (hero, primary-cta, secondary-cta, header, footer, social-website, and the other listed values)
  • utm_term = the send (announce, reminder, last-call, or a documented custom term such as drip-1)

Do not enable Brevo's native GA integration as a substitute for explicit UTMs. Still set the campaign utmCampaign field to the slug so Brevo's own field matches. Instagram and Facebook links get no UTMs.

Chrome links (logo, footer, website icon) are stamped by compose.mjs when you pass campaignSlug and campaignTerm. Do not duplicate them in blocks.

Phase 3: Image

Read Filename and Location from the brief. Resolve Location to a local file or an already-public HTTPS URL.

Steps:

  1. If Location is a local file or folder, copy the named file to email/assets/<filename> (keep the brief filename when it is already a clean slug; otherwise use <campaign-slug>-<term>.<ext>).
  2. Publish it to a fetchable HTTPS URL. Preferred host, matching sent rum emails: https://sugarhousedetroit.com/images/email/<filename> once that file is on the live site. Copy into site/public/images/email/ for the next site deploy. If it is not live yet this session, upload to the Sugar House R2 bucket used for public GBP images (gbp-images-sugar-house) and use that bucket's managed public domain in the email src. Uploading the same URL to the Brevo gallery is optional; a public R2 or site URL that returns 200 is enough.
  3. Confirm the hosted image returns 200 and is jpeg/jpg/png under 2MB.
  4. Use the brief's alt text. If the brief has none, write one factual sentence. No keyword stuffing.

compose.mjs image blocks accept optional href. Link the hero when the brief gives a Linked URL; rum story images were often unlinked.

Phase 4: Map the brief to blocks

Save a build spec under:

email/builds/<campaign-slug>-<term>.json

Required fields: subject, preheader, campaignSlug, campaignTerm, measurement, blocks.

measurement is the send's scoring contract. Compose ignores it; the send grader (scripts/grade-email-send.py) reads it. Translate the brief's

Measurement section into this object when writing the build:

"measurement": {
  "primary": "clickers | ticket_sales | visit_intent",
  "secondary": ["menu_sessions", "visit_clicks", "class_page_sessions", "ticket_sales", "reservation_handoffs", "clickers", "click_rate", "unsubs", "complaints"],
  "ignore": ["opens"],
  "outcome_window_hours": 72,
  "guardrails": { "complaint_rate_max_pct": 0.1 },
  "notes": "optional one-liner from the brief"
}
  • Class drip → primary: "ticket_sales", secondary includes clickers + class_page_sessions.
  • Menu / visit invite → primary: "clickers" or "visit_intent", secondary includes menu/visit signals; reservation handoffs stay directional.
  • Always ignore opens (MPP). Complaint guardrail stays 0.1% unless the brief says otherwise.

After Brevo create, write brevoCampaignId onto the same build JSON so the grader can join without scraping the brief.

Map brief sections to compose.mjs block types. Choose the layout by the email's job. Do not default every send to the rum series.

Story-led (class drip, origin lesson, one fact per send): rum model. Eyebrow, headline, greeting, several short paragraphs, image mid-lesson as illustration, more copy, callout, close. The image can sit later because the copy is the exhibit.

Invitation (seasonal menu, event, promo, schedule): exhibit model. The picture is the argument. Keep setup short enough that the image appears after one or two paragraphs, then write a caption that points at what is in the frame. Then the CTA.

  1. eyebrow, headline, greeting
  2. One or two short setup paragraphs. No parable. Give the image a reason to exist.
  3. image. Linked when it goes to the primary destination.
  4. One or two paragraphs that name what the reader is looking at, then make the invitation
  5. callout
  6. Secondary note as details plus inline_link. No second dark callout
  7. close

Do not park the image immediately above the CTA with nothing after it. That reads as a spacer. Do not put the image first with no setup. That reads as a header graphic. Do not import rum length onto a menu send.

Class lineup emails may use link_list or details instead of a single callout.

Greeting: ignore a raw Hey {{ contact.FIRSTNAME }}, line; the renderer already has the if/else fallback. Close with See you at the bar,<br>The Sugar House team unless the brief specifies something else.

Rules:

  • Do not invent copy, recipes, testimonials, or class inclusions
  • No em dashes, including HTML entities
  • Bitters in dashes
  • Greeting uses {% if contact.FIRSTNAME %} / {% else %}Hey there,{% endif %}. Never | default:
  • Button labels stay as briefed; compose.mjs already uppercases via CSS
  • Block URLs are used as-is. Stamp UTMs on them before compose
  • If a button label and its URL disagree, route to the destination that matches the label and the surrounding copy, stamp UTMs, and tell the user in the handoff. Do not silently keep a leftover menu URL on a visit button

Build HTML with:

node email/build.mjs email/builds/<campaign-slug>-<term>.json > /tmp/<campaign-slug>-<term>.html

Do not hand-author the chrome. Do not start from email/templates/sh-master-template.html.

Phase 5: QA before Brevo

Check the built HTML:

  • Subject and preheader match the brief
  • No em dashes
  • Every sugarhousedetroit.com href includes all five UTM parameters
  • Every such href has a trailing slash before ?
  • Chrome links include utm_term
  • Destinations fetched live this session and returned 200
  • Image src is HTTPS, has alt text, and the file loads
  • Unsubscribe token {{ unsubscribe }} is present (chrome provides it)
  • No tag will be sent to the create call (it 500s on this account)

Cadence: if this send would be a third marketing email to the same people in the same week, stop and say so.

Phase 6: Create the Brevo draft

Resolve audience live by name:

  • Default for broad content and class-story sends: segment Marketable (All), excluding segment Visitor. That is the rum / absinthe / World Whisky pattern
  • A class-schedule dump may target Marketable (All) with no exclusion if the brief says so and the last comparable send did that
  • Never union extra lists onto a segment. Brevo unions lists and segments, it does not intersect
  • One self-contained audience per send

Create with email_campaign_management_create_email_campaign:

  • name: YYYY-MM-DD_<type>_<slug>_<stage>_<audience>, all lowercase. Underscores separate tokens, hyphens live inside them. Derive it, do not compose it by hand: the date is scheduledAt, <slug> is the build's campaignSlug (identical to utmCampaign below), <stage> is its campaignTerm. <type> is one of class event menu vault promo review lifecycle merch. <audience> defaults to all; use all-x-visitor for the standard exclusion, or the segment shorthand when a second send of the same slug goes elsewhere. Example: 2026-08-17_class_mix-207-09-26-26_announce_all-x-visitor. The name must never contain a space, a slash, or an em dash. Brevo falls back to the campaign NAME as utm_campaign when utmCampaign is empty, and five March sends are sitting in GA4 under names like Warm Up 1 - Welcome Back Class Review - MC K-Z because of it
  • sender: { "email": "info@sugarhousedetroit.com", "name": "Sugar House Detroit" } or the live sender id plus that name. Never both email and id
  • replyTo: info@sugarhousedetroit.com
  • subject, previewText, htmlContent from the build
  • recipients: { "segmentIds": [...], "exclusionSegmentIds": [...] }. Create rejects segments / excludedSegments; those names appear only on GET
  • scheduledAt: the brief time as an offset datetime, e.g. 2026-08-14T11:30:00-04:00 (America/Detroit). Setting this schedules the campaign. That is intended: the user approves a timed draft, not a send-now
  • mirrorActive: true
  • utmCampaign: the campaign slug
  • Do not pass tag
  • Do not send (send_email_campaign_now is forbidden here)

If a draft for this exact send already exists, update that draft instead of creating a duplicate. Never PUT htmlContent onto a draft the user has edited in the Brevo UI this session.

After create, fetch the campaign back and confirm:

  • status is draft or queued (queued means the schedule is attached; it has not sent)
  • subject, preview, sender name, recipients, and scheduledAt
  • HTML still contains the UTM-coded links and the hosted image

Completion boundary

The workflow ends when the Brevo draft exists and has been re-fetched.

Before handing it off, verify:

  • Copy matches the brief
  • Links are live and UTM-complete
  • Image loads
  • Audience matches the brief or the documented default
  • Scheduled time matches the brief in America/Detroit
  • Cadence is still at most two marketing sends that week
  • Nothing was sent

Append a short Built note to the brief: Brevo campaign id, scheduled time, audience names, image URL, and the build spec path.

Final handoff

Report:

  • Brevo campaign id and name
  • Subject / preview
  • Audience (names, then IDs as resolved live)
  • Scheduled time in ET
  • Image URL used
  • Link QA (destinations + UTM)
  • Cadence note
  • Confirmation that the campaign was not sent
  • Anything the user must check before the scheduled time (sender name, a flagged page defect, a missing Tock widget)

Suggested invocation

Run sh-email-compose using @clients/sugarhouse/content/campaigns/midnight-munchies.md

Sugar House Class Campaign Playbook

Purpose

Turn a Sugar House class idea into a researched campaign brief with complete email copy without losing the quality, voice, or measurement discipline established by the successful rum, absinthe, World Whisky, and Cocktail Foundations campaigns.

This file is the recipe for the first slice of the class-email workflow. The Cursor skill is only the initializer. The workflow lives in this folder.

Scope

Research the class, design the campaign arc, write every email, and save the campaign brief. This playbook ends at the finished brief.

Do not compose HTML, source images, create or update Brevo drafts, schedule campaigns, or send email. After the user edits the brief and adds the hero image filename and location, that handoff is sh-email-compose / brevo-compose-playbook.md.

Minimum input

The user should provide:

  • Class name or Mixology number
  • Class date
  • Desired number of emails
  • Desired send dates
  • The best available class-notes, handout, deck, or source file

Optional but useful:

  • A positioning idea or audience concern
  • Whether several related classes should share one campaign
  • A known deadline, event tie-in, or seasonal hook

Do not make the user restate stable Sugar House context. Load it.

Source priority

Use sources in this order:

  1. Live class page for the current public offer, date, time, and confirmed experience
  2. Class notes or handout for curriculum, recipes, technique, and factual depth
  3. Private-class deck for positioning and curriculum summaries
  4. Brevo for sent campaign content, audiences, and performance
  5. Client canon for voice, measurement, and operating rules
  6. Reputable external sources for facts that are absent or need verification

When sources disagree, flag the contradiction. Do not silently choose the version that makes better copy.

Phase 1: Initialize the client

Read these before drafting:

  1. .claude/CLAUDE.md
  2. measurement-plan.md
  3. context.yaml
  4. brand-narrative.md
  5. email/SESSION-INIT-email-campaigns.md

Treat orientation as read-only. Confirm the connected Brevo account, current audience names, recent sent campaigns, current drafts, and live templates. Resolve all IDs live rather than copying them into this playbook.

Pull at least:

  • The latest class-schedule campaign
  • The most relevant successful story-led class campaign
  • Any earlier campaign for the same class or spirit
  • Current performance for those sends

Use clicks and ticket sales as the scoreboard. Opens are directional because Apple Mail Privacy Protection inflates them.

Phase 2: Establish class truth

Read the supplied source file to completion. Large self-contained HTML handouts often contain embedded fonts and images, so search for headings and read the content section rather than dumping the entire file.

Open the live class page and verify:

  • Class title and number
  • Date and time
  • Duration
  • Confirmed tastings and builds
  • Audience framing
  • Public description
  • Booking URL

Check for copied text from another class, mismatched spirit names, stale dates, or unsupported promises. Put defects in a Preflight issue section of the brief. Do not let a page defect leak into email copy.

Use web research when a factual story will carry an email. Prefer primary sources, respected reference works, established publications, and recognized category authorities. Keep a short fact ledger in the brief.

Phase 3: Learn from prior campaigns

Do not copy an old campaign's topic. Reuse the proven persuasion model:

  1. Give the reader a complete and interesting story.
  2. Teach with authority and generosity.
  3. Reserve the sensory comparison, bartender feedback, and hands-on build for the class.
  4. End with a concrete invitation.

The strongest Sugar House class emails use:

  • A bartender with an opinion, not a brochure narrator
  • One memorable fact, conflict, transformation, or technique per email
  • Specific sensory language
  • A clear bridge from knowing to tasting or building
  • Increasing CTA strength across the series
  • A callback or progression that makes the sends feel related

Avoid turning three emails into three versions of the same announcement.

Phase 4: Design the arc

Give each email one job.

A useful three-email progression:

  1. Reframe a myth, origin, or category misunderstanding.
  2. Make the class tangible through a sensory transformation or production insight.
  3. Convert through a cocktail, technique, or familiar point of entry.

For two emails:

  1. Establish the central argument and why the class matters.
  2. Make the curriculum practical and give the strongest invitation.

Five-part campaigns are not the default. Use fewer, better sends unless the sales window and available material justify more.

Before drafting, write the arc as:

  • Send date
  • Job
  • Angle
  • Lesson
  • CTA strength

Reject an arc if two emails teach substantially the same thing.

Copy rules

Every draft must follow these rules:

  • Bartender point of view with an actual opinion
  • Useful before promotional
  • Clear enough for a curious beginner without talking down to an enthusiast
  • One primary action per email
  • Short paragraphs suitable for mobile
  • Specific facts and real technique names
  • No invented recipes, bottle details, testimonials, or class inclusions
  • No em dashes, including HTML entities
  • No fake urgency
  • Never disclose remaining seat counts
  • No discount-led framing
  • No generic newsletter language
  • No actual-speakeasy, hidden-door, password, or exclusivity framing
  • Bitters are measured in dashes
  • Sugar House is a craft cocktail bar, not a restaurant

Do not withhold the educational payoff to manufacture curiosity. The class sells the tasting, comparison, correction, and hands-on build.

Subject and preview

  • Prefer clear specificity or genuine curiosity over wordplay.
  • Keep the subject focused on the story, not the class number.
  • Use the preview to complete the thought rather than repeat the subject.
  • Provide one subject alternative.
  • Do not use an emoji by default.

CTA progression

Escalate naturally:

  • Early: See the Class, Explore the Class
  • Middle: Taste the Difference, Build the Drink
  • Final: Save Your Spot, Join the Class

Use a stronger custom CTA when the email's lesson supports it.

Tracking rules

Follow the UTM vocabulary in measurement-plan.md.

For a single class instance:

  • utm_source=brevo
  • utm_medium=email
  • utm_campaign=mix-<level>-<MM-DD-YY>
  • utm_content identifies placement
  • utm_term identifies the send

Preferred send terms are:

  • announce
  • reminder
  • last-call

For a campaign promoting multiple class instances, individual class links use their class-instance campaigns. A series landing-page CTA may use a descriptive series campaign documented in the brief.

Do not enable Brevo's native GA integration as a substitute for explicit UTMs.

Deliverability and cadence

Before recommending or drafting dates:

  • Keep marketing density at no more than two sends per week per contact.
  • Account for already scheduled or recently sent campaigns.
  • Prefer excluding low-intent audiences when a verified prior pattern supports it.
  • Stop later class sends when the class sells out.
  • Treat a complaint rate under 0.1 percent as the guardrail.
  • Flag unusual bounce spikes rather than averaging them away.
