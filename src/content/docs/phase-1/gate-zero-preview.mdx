Before anyone sketches an "agent," two questions need separate answers. Collapsing them is how a filter plus one templated call becomes a multi-agent science project.

## Stage 1: Ready?

Is this process automatable at all?

| Signal | Meaning |
| --- | --- |
| Undocumented or changes weekly | Standardize first |
| Staff would not make the same decisions | No rubric yet, cannot grade |
| Real blocker is data access | Corpus problem, not model problem |

Often **"we need an agent" is documentation or data-access need wearing a costume.**

## Stage 2: Shape?

Once ready, what runs it?

| Character | Shape |
| --- | --- |
| Clear rules, stable, structured data | Rule or script |
| Mostly rules, messy input | Script + one templated LLM call |
| Real judgment, fixed flow | Workflow / prompt graph |
| Flow varies per input | Harness (full agent) |

**Governing idea:** decide where non-determinism lives. The model belongs at build time or at a narrow checkpoint, not as the runtime that re-reasons over all data every execution.

A cron plus a script plus one templated call is not a lesser agent. It is correct placement.

## Two axes: do not conflate

| Axis | Question |
| --- | --- |
| **Authority** | AUTOMATE / ASSIST / HUMAN, who acts? |
| **Shape** | rule / script / workflow / harness, what runs? |

They are orthogonal. A script can AUTOMATE. A harness can ASSIST.

Phase 2 goes deeper on design. Phase 1 ends with an activity, classify a real team idea.
