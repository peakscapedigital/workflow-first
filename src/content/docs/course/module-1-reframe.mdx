**Time:** ~25 minutes  
**Goal:** Replace the default mental model — "AI = chat window" — with workflow units and agent senses.

## 1. The chatbot trap (~5 min)

Most enablement stalls because the unit of progress is wrong:

| Wrong unit | What happens |
| --- | --- |
| Seat / license | Usage metrics move; work does not |
| Persona / role | Charter grows; context rots; nobody knows when it is done |
| Prompt | Judgment lives in someone's head; cannot test or transfer |

The alternative: **one bounded workflow** with an exit condition, measured this quarter.

Discuss: What is your team's default unit today — seat, persona, or workflow?

## 2. Three senses of agent (~8 min)

Read the [Three senses of agent](/concepts/three-senses-of-agent/) reference (or summarize from the table):

- **Sense A** — scoped assistant on a tenant (most enterprise rollouts)
- **Sense B** — orchestrated workflow with an exit condition (where value compounds)
- **Sense C** — autonomous persistent agent (rare; heavy governance)

Key line: **same workflow unit, different wrapper.**

## 3. Workflow vs role (~7 min)

A workflow has an exit condition. A role does not.

Run the [log-vs-profile diagnostic](/concepts/workflow-is-the-unit/#the-log-vs-profile-diagnostic):

> Is anything in this bot's log that is not in its profile?

If no — you have a workflow wearing a persona mask.

## 4. Gate 0 preview (~5 min)

Two questions people merge:

1. **Ready?** — Is the process automatable?
2. **Shape?** — Rule, script, workflow, or harness?

Preview only — Module 2 goes deeper. See [Gate 0](/concepts/gate-zero/).

---

## Activity (~10 min)

Pick one "AI agent" idea your team has floated. On paper:

1. Which **sense** (A / B / C)?
2. **Workflow or role?** — Is there an exit condition?
3. One sentence: what would "done" look like?

Share one example with the group.
